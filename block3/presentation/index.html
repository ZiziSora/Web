Student Management SSR

Ứng dụng quản lý danh sách sinh viên xây dựng theo kiến trúc Server-Side Rendering với sự hỗ trợ của AI Agent.

Node.js ≥ 18 Express 5.x EJS JSON Storage
Bài toán

Xây dựng ứng dụng web cho phép xem danh sách và thêm sinh viên mới, với dữ liệu được render tại server.

Mục tiêu SSR

HTML hoàn chỉnh được tạo tại server trước khi gửi về browser — không cần JavaScript phía client để hiển thị dữ liệu.

Tại sao đây là SSR? — HTML được render tại server (Express + EJS), trước khi gửi về browser. Browser chỉ nhận HTML hoàn chỉnh và hiển thị — không cần chạy JavaScript để fetch dữ liệu. Việc lấy dữ liệu từ JSON file ở server không quyết định CSR hay SSR; điều quyết định là HTML được tạo ở đâu.

Decision: Tại sao chọn Express + EJS?
Requirement

Xây dựng ứng dụng SSR nhỏ trong thời gian giới hạn; HTML phải được render hoàn toàn tại server.

Alternatives đã cân nhắc
Express + EJS — SSR thuần, ít setup, EJS là template engine render HTML ở server
Express + React (CSR) — HTML render ở browser → không đáp ứng yêu cầu SSR
Next.js / Nuxt.js — hỗ trợ SSR tốt nhưng phức tạp hơn scope bài toán
Rationale

EJS render HTML tại server và tích hợp trực tiếp với Express qua res.render(). Luồng SSR rõ ràng: route → data → template → HTML response. Phù hợp scope, không over-engineer.

Trade-off: EJS không hỗ trợ component tái sử dụng như React. Chấp nhận được với ứng dụng nhỏ, ít interactivity ở client.

07 / 13Implementation

Route POST & Input Validation

Controller — create()
async create(request, response, next) { const validation = validateStudentInput(request.body); if (!validation.valid) { return response.redirect(303, `/students?error=${validation.errorCode}`); } try { await store.create(validation.student); return response.redirect(303, '/students?status=created'); } catch (error) { if (error instanceof DuplicateStudentEmailError) { return response.redirect(303, '/students?error=duplicate_email'); } return next(error); } }
Validator — validateStudentInput()
const EMAIL_PATTERN = /^[^\s@]+@[^\s@]+\.[^\s@]+$/; function validateStudentInput(input = {}) { const name = input.name?.trim() || ''; const email = input.email?.trim() || ''; if (!name || !email) return { valid: false, errorCode: 'required' }; if (!EMAIL_PATTERN.test(email)) return { valid: false, errorCode: 'invalid_email' }; return { valid: true, student: { name, email } }; }
Validation rules
✗ required — Họ tên hoặc email bỏ trống
✗ too_long — Tên > 100 ký tự, email > 254
✗ invalid_email — Sai định dạng email
✗ duplicate_email — Email đã tồn tại (case-insensitive)
Post-Redirect-Get (PRG): Sau POST thành công → redirect 303 về GET /students. Khi user nhấn F5, browser gửi lại GET — không tạo bản ghi mới.
Tại sao không chỉ dùng HTML required? Attribute này có thể bị bypass bằng DevTools hoặc curl. Validation luôn phải được thực hiện ở server.

11 / 13Decisions

Thách thức & Quyết định kỹ thuật

⚠ Vấn đề phát sinh

Sau POST thành công, user nhấn F5 → browser gửi lại POST request → tạo bản ghi trùng lặp.

→ AI đề xuất

Re-render template với thông báo thành công ngay sau POST (không redirect về GET).

✓ Quyết định cuối cùng

Post-Redirect-Get (PRG): Redirect 303 về GET /students sau POST thành công. Refresh → browser gửi lại GET, không POST.

⚠ Vấn đề phát sinh

Sau redirect, không thể truyền error message qua request body — context request đã thay đổi.

→ AI đề xuất

Dùng session hoặc flash message để lưu error qua redirect — cần thêm middleware phức tạp.

✓ Quyết định cuối cùng

Error code qua query param: redirect(303, '?error=required'). Controller đọc param, map sang message. Đơn giản, zero dependency.

⚠ Vấn đề phát sinh

Lựa chọn storage: in-memory array hay JSON file? Dữ liệu sẽ mất khi server restart nếu dùng in-memory.

→ AI đề xuất ban đầu

In-memory array — đơn giản hơn, không cần xử lý file I/O bất đồng bộ.

✓ Quyết định cuối cùng

JSON file: Dữ liệu persist qua các lần restart. Phù hợp hơn với yêu cầu thực tế. Trade-off: cần async file I/O.

12 / 13Decisions

Minh chứng Post-Redirect-Get (303)

Network Trace: Khi POST thành công, server trả về 303 See Other kèm theo Location: /students?status=created. Browser ngay lập tức thực hiện một HTTP GET để tải trang.
