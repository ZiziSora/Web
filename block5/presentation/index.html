Các URL để xem và tìm món ăn

Các route dưới đây dùng GET: đọc nội dung hoặc điều hướng, không sửa dữ liệu nghiệp vụ.

MethodURLHành viResponse thành công
GET/Đi tới thực đơn302 → /dishes
GET/dishes?q=...Danh sách, tìm tên món qua q200 · HTML
GET/dishes/:idChi tiết món, đầu bếp và nguyên liệu200 · HTML
GET/adminĐi tới quản lý món ăn302 → /admin/dishes
Query và path parameter

q là nội dung tìm kiếm; :id là ID bản ghi.
Không có q thì hiển thị toàn bộ danh sách.

Trường hợp không tìm thấy

ID sai định dạng hoặc không có → 404.
Tìm không có kết quả → 200, danh sách rỗng.

07 / Method override

Browser gửi POST, Express xử lý PATCH

Form giữ hành vi submit mặc định; middleware chuyển method trước khi chọn route.

views/admin/form.ejsLược trích · HTML sau render, ID ví dụ
<form action="/admin/dishes/1"
      method="post">
  <input type="hidden"
         name="_method" value="PATCH">
  <!-- Các input của món ăn -->
  <button type="submit">Lưu</button>
</form>
Đối với xóa

Form trên trang xác nhận dùng _method=DELETE, kèm chữ ký xác nhận và thời hạn.

src/app.tsLược trích · định dạng lại
app.use(express.urlencoded({
  extended: false, limit: '32kb',
  parameterLimit: 500
}));
app.use(methodOverride(req => {
  if (req.method === 'POST' &&
      ['PATCH', 'DELETE']
        .includes(req.body?._method))
    return req.body._method;
}, { methods: ['POST'] }));

Phải đọc body trước override. Không lấy method từ query string và không cho override GET.

POST + _method=PATCHRequest thật trên Network
→
methodOverrideThay req.method
→
app.patch(... )Route cập nhật trên server

08 / GET → dữ liệu → HTML

Server đọc dữ liệu rồi render EJS

Tìm kiếm tải một document mới; nội dung món ăn đã nằm trong HTML response.

app.get('/dishes', async (req, res) => {
  const q = typeof req.query.q === 'string'
    ? req.query.q.trim() : '';
  const dishes = await store.list('dishes', q);
  res.render('dishes/index', {
    pageTitle: 'Thực đơn', dishes, q
  });
});
Trong Prisma store

findMany tìm tên bằng contains, không phân biệt hoa/thường; tải cả quan hệ đầu bếp và nguyên liệu.

src/app.ts · load()Lược trích · định dạng lại
const load = async (resource: Resource,
                    raw: unknown) => {
  const id = parseId(raw);
  if (!id) throw new NotFoundError();
  const entity = await store.find(resource, id);
  if (!entity) throw new NotFoundError();
  return entity;
};
Chi tiết /dishes/:id

load() kiểm tra ID và bản ghi. Có dữ liệu thì render dishes/show; lỗi được middleware chuyển thành trang 404.

src/app.ts · POST tạo mớiLược trích · nhánh lỗi khác được bỏ
const values = formValues(req.body);
try {
  await store.create(resource,
    validate(resource, values));
  return res.redirect(303, `${base}?status=created`);
} catch (error) {
  if (error instanceof InputError)
    return renderForm(res, resource, undefined,
      values, error.errors, 400);
  // Lỗi khác được ném tiếp tới error middleware.
}

10 / Post · Redirect · Get

Vì sao ghi thành công phải redirect 303?

Tách request ghi dữ liệu khỏi trang kết quả; browser tải lại trang đích bằng GET.

Đọc từ trên xuống. Mũi tên liền: request/lời gọi; nét đứt: response/kết quả. Database được truy cập qua store và Prisma.

src/app.tsLược trích · định dạng lại
await store.create(resource,
  validate(resource, values));
return res.redirect(303,
  `${base}?status=created`);
Sau redirect

Reload → GET danh sách

Không gửi lại request tạo mới. Thông báo thành công dựa vào query status.

Giới hạn của cơ chế

PRG tránh lặp khi reload trang đích; không phải cơ chế chống mọi trường hợp gửi trùng request.

Cập nhật và xóa thành công cũng trả 303 về danh sách tương ứng.

Quy tắc theo tài nguyên

12 / Những quyết định bảo vệ dữ liệu

Kiểm soát input, dữ liệu và lỗi trả về

Chọn dữ liệu được ghi, escape khi hiển thị và trả status theo tình huống cụ thể.

Trước khi ghi
  • Allowlist: lấy trường đã định nghĩa; không truyền thẳng req.body cho Prisma.
  • Giá: lưu Decimal(12,2); không chuyển qua số thực khi ghi.
  • Truy vấn: dùng Prisma; không nối input vào raw SQL.
Khi hiển thị và cấu hình
  • <%= value %> escape dữ liệu trong EJS.
  • DATABASE_URL ở .env, được gitignore; log lỗi ứng dụng không in chuỗi kết nối.
StatusKhi nào?Ứng xử
400Input sai, xác nhận sai hoặc nguyên liệu đang dùngRender lỗi; giữ input form
404ID sai, bản ghi hoặc URL không cóTrang không tìm thấy
500Lỗi hệ thống/databaseThông báo thân thiện
Phân biệt lỗi và thành công

Input sai không redirect sang trang thành công. Chỉ ghi hoàn tất mới trả 303.

400 ở form thêm/sửa giữ values; 400 ở luồng xóa hiển thị lại trang xác nhận hoặc lý do chặn.
